# cord

Flutter web app. This is developed on a Windows host, but **the Flutter/Dart SDK only exists inside the project's devcontainer** (`.devcontainer/Dockerfile`, `.devcontainer/devcontainer.json`) — it is never installed on the host. Do not expect `flutter`/`dart` to be on the host PATH; running them directly via Bash/PowerShell on the host will fail with "command not found".

## Running Flutter/Dart commands

The repo is bind-mounted into the devcontainer at `/workspace`. If a container is running (check `docker ps`), run commands via `docker exec <container> bash -lc "cd /workspace && flutter analyze"`. Otherwise open the folder in VS Code and "Reopen in Container", or build/run from `.devcontainer/Dockerfile` directly (see README). Ask the user before building/running a new container — that's heavier than exec-ing into one that's already up.

The container builds Flutter stable with web support enabled and Google Chrome installed. Port 8080 is forwarded for `flutter run -d web-server --web-port 8080`.

## Structure

- The app's pages live in one registry: `appPages` in `lib/pages/app_pages.dart`. Both the frontpage's link cards (`lib/pages/home_page.dart`) and the named routes (`lib/main.dart`) are generated from it. **To add a page**, add a widget under `lib/pages/` and append an `AppPage` entry — do not wire routes or home-screen cards by hand, or the two will drift.
- The **Search** page (`lib/pages/search_page.dart`, first registry entry / top link) filters `buildSearchIndex()` from `lib/pages/search_index.dart`, which is built from `appPages` + `tallySystems` + `hanziScripts` + Latin's `Alphabet.values` + Greek's + Makasar's `WritingScript.values`. A page with its own dropdown content should contribute its items there (as those five do) so search stays complete. Tally results open `TallyPage(initialSystem:)` reflecting into `?system=`, Hanzi Grid results open `HanziGridPage(initialScript:)` and Makasar results `MakasarPage(initialScript:)`, both reflecting into `?script=`, Latin results open `LatinPage(initialAlphabet:)` and Greek results `GreekPage(initialAlphabet:)`, both reflecting into `?alphabet=` — keep those params if you refactor any of those pages. Latin and Greek each have an `Alphabet` enum of their own and they are unrelated, so `search_index.dart` imports Greek's under a prefix rather than either being renamed.
- **`dart:html` cannot be imported by anything a widget test touches**: `flutter test` runs on the VM, where the import is a *compile* error, so it takes down the whole test file. The tally page imports it directly and gets away with it only because nothing tests that page. Hanzi Grid needs the same `?script=` URL sync and *is* tested, so its one web-only call sits behind a conditional import (`lib/hanzi/pages/script_param.dart` → `_web`/`_stub`), Makasar has its own for its own `?script=` (`lib/makasar/pages/script_param.dart`), and Latin and Greek do the same for `?alphabet=` (`lib/latin/pages/alphabet_param.dart`, `lib/greek/pages/alphabet_param.dart` — a shim each, since features share nothing). Use that idiom for any new page that syncs the URL. Reading `Uri.base.queryParameters` needs no shim — it works on the VM and simply finds nothing.
- **Never `pumpAndSettle` a page holding a `GameCanvas`**: the engine's `Ticker` runs unconditionally, so a frame is always pending and settling times out instead of finishing. Pump fixed durations to run a route or menu transition out (see `settle()` in `test/hanzi/hanzi_grid_page_test.dart`).
- **Every drawing feature — tally (`lib/tally/`), Futhark (`lib/furthak/`), Tifinagh (`lib/tifi/`), Hangul (`lib/hangul/`), Hangul Grid (`lib/hangul_grid/`), Hanzi Grid (`lib/hanzi/`), Hebrew (`lib/hebrew/`), Cyrillic (`lib/cyrillic/`), Latin (`lib/latin/`), Greek (`lib/greek/`), Makasar (`lib/makasar/`), and the rest — lives under its own top-level folder and is deliberately kept fully isolated: nothing is shared between them.** Their assets are likewise grouped per feature under `assets/<feature>/` (most have none — they draw vectors). Each has its OWN copy of the engine (`scene.dart` + `game_canvas.dart`) and its own scene/data. Do NOT "de-duplicate" the engine copies into one shared engine, and do not have one feature import another's code — the separation is intentional and requested. The only shared code is the app shell (`main.dart`, `app_pages.dart`, `home_page.dart`, `search_page.dart`).
- **Futhark** (`lib/furthak/`, ported from the `furthak` app): desktop shows the rune reference table beside the canvas (50/50); narrow shows an info button opening the tabbed `reference_page.dart`. Runic glyphs need the bundled `NotoSansRunic` font (Flutter web has no system fallback for the Runic block).
- **Tifinagh** (`lib/tifi/`, ported from the `tifi` app) is **without the Neo-Tifinagh variants**: the dropdown offers the 5 Tuareg regions + Libyco-Berber, and `reference_page.dart` has Tuareg + Libyco-Berber tabs only (no `neo_tifinagh_scripts.dart` was copied). The recognizer scene (`tifinagh_scene.dart`) is otherwise verbatim and still contains its Neo-Tifinagh classifiers internally — they're just never selected. Needs the bundled `NotoSansTifinagh` font and the `assets/tifi/libyco_berber/` images (loaded by the scene via `rootBundle` and by the table via `Image.asset`).
- **Hebrew** (`lib/hebrew/`, ported from the `heb` app) is **without Paleo-Hebrew**: only the modern square alef-bet (22 letters + 5 final forms), so there is no script dropdown and none of the paleo reference data (`paleo_glyphs.dart`, `assets/paleo/`, `paleoSignRows`) was copied. The recognizer scene (`hebrew_scene.dart`) is otherwise verbatim and still contains its whole Paleo-Hebrew mode internally — `HebrewLayer.script` is simply never moved off `HebrewScript.modern`, which is why the `HebrewScript` enum and `paleoGlyphs`/`glyphIn` stay in `hebrew_letters.dart`. Same idiom as Tifinagh above; upstream `heb` also holds the paleo tests, so `test/hebrew/hebrew_scene_test.dart` is its test file minus that group. Hebrew glyphs need no bundled font (unlike Runic/Tifinagh, the block has system/browser fallbacks). Where several letters share a shape drawn alone (resh/yod, vav/final nun, dalet/final chaf) the recognizer reports one base glyph and names the group — see `HebrewLayer.sharedGroups`, which the legend reads too.
- **Cyrillic** (`lib/cyrillic/`, ported from the `cyrillic` app) is the whole app, not a slice of it: `engine/`, `data/cyrillic_letters.dart` and `scenes/cyrillic_scene.dart` are verbatim (the engine files are byte-identical to the other features' copies), and `test/cyrillic/cyrillic_scene_test.dart` is upstream's test file with only its package import repointed. Only the page was re-shaped into cord's house layout — upstream's single page put the legend in a `Wrap` under the canvas; here it is split into `pages/cyrillic_reference.dart` + `pages/reference_page.dart` and shown 50/50 beside the canvas on wide screens, behind an app-bar info button on narrow, like Tom-Tom/Hebrew. The recognizer covers all 33 Russian letters, so nothing is muted today — the legend still reads `CyrillicLayer.recognizedNames` (as upstream's did) so it can't drift if that set changes. Ё is the one letter drawn with taps rather than drags (an Е plus two dots). Cyrillic glyphs need no bundled font.
- **Latin** (`lib/latin/`, ported from the `latin` app) is the whole app, not a slice of it: `engine/`, `data/latin_letters.dart` and `scenes/latin_scene.dart` are verbatim (the engine files are byte-identical to the other features' copies), and `test/latin/latin_scene_test.dart` is upstream's test file with only its package imports repointed. Only the page was re-shaped into cord's house layout — upstream's single page put the legend in a `Wrap` under the canvas; here it is split into `pages/latin_reference.dart` + `pages/reference_page.dart` and shown 50/50 beside the canvas on wide screens, behind an app-bar info button on narrow, like Cyrillic/Hebrew. 111 letters over **31 alphabets** are drawable, so nothing is muted today — the legend still reads `LatinLayer.recognizedNames` (as upstream's did) so it can't drift if that set changes. The **alphabet dropdown** (the verbatim `Alphabet` enum — the single source for the dropdown, the legend and the search index) narrows what may be *reported*, not what may be drawn: a shape the chosen alphabet has no letter for falls through to the next classifier, so a U under `Alphabet.latin` comes out as V. Its slug is the enum's own `.name` (`?alphabet=icelandic`), so nothing is kept in step by hand; `alphabetForSlug` lives in `pages/latin_page.dart` and falls back to English. URL sync goes through the `pages/alphabet_param.dart` → `_web`/`_stub` shim, since the page is widget-tested. `test/latin/latin_page_test.dart` is upstream's page test re-aimed at that layout, plus cord's own three (initial alphabet, unknown slug, narrow layout) — and it sizes `tester.view` rather than calling `setSurfaceSize`, which moves the render surface but *not* `MediaQuery`, so a page laid out that way reads the wrong breakpoint. Latin glyphs need no bundled font.
- **Greek** (`lib/greek/`, ported from the `greek` app) is the whole app, not a slice of it: `engine/`, `data/greek_letters.dart` and `scenes/greek_scene.dart` are verbatim (the engine files are byte-identical to the other features' copies), and `test/greek/greek_scene_test.dart` is upstream's test file with only its package imports repointed. Only the page was re-shaped into cord's house layout — upstream's single page put the legend in a `Wrap` under the canvas; here it is split into `pages/greek_reference.dart` + `pages/reference_page.dart` and shown 50/50 beside the canvas on wide screens, behind an app-bar info button on narrow, exactly as Latin/Cyrillic are. All 26 letters are drawable, so nothing is muted today — the legend still reads `GreekLayer.recognizedNames` (as upstream's did) so it can't drift if that set changes. The **alphabet dropdown** works exactly like Latin's, and its three alphabets are separated by **date rather than language**: Greek (the classical 24 of Α–Ω), Old Attic (the 21 before 403 BC, no Ξ/Ψ/Ω) and Archaic (23, with Ϝ and Ϙ). Like Latin's it narrows what may be *reported*, not what may be drawn — an Ω under Old Attic falls through to the Λ its stroke also describes, while a Ξ, having nothing to fall through to, reads as nothing. Its slug is the enum's own `.name` (`?alphabet=oldAttic`); `alphabetForSlug` lives in `pages/greek_page.dart` and falls back to Greek. **Ϝ is the one letter with two ways in**: a stem with two arms off its right, each arm either a flat bar or a **ㄱ** hooking down at its tip, in three strokes or in two (the Γ-corner plus a bar) — `_isDigamma`/`_isDigammaArm` in the scene, and note the ㄱ is *not* mirrored the way Γ's own corner is. **There is no mark machinery at all** — no tonos, no dialytika, and so no taps: upstream stripped Latin's mark tables and dot handling, and the tier that brings them back wants a `_sitsAboveLeft` beside `_sitsAbove`, since a capital's tonos sits to its upper *left* (see upstream's `TODO.md`). Nineteen classifiers are shared shapes with `latin`/`cyrillic`, so a shape fix here is usually a fix there too — upstream's `CLAUDE.md` lists which. `test/greek/greek_page_test.dart` is upstream's page test re-aimed at that layout, plus cord's own three (initial alphabet, unknown slug, narrow layout), sizing `tester.view` rather than calling `setSurfaceSize` for the reason Latin's does. Greek glyphs need no bundled font.
- **Makasar** (`lib/makasar/`, ported from the `makasar` app) is the whole app, not a slice of it: `engine/`, `data/` (`makasar_letters.dart`, `lontara_letters.dart`, `script.dart`), `scenes/` (`makasar_scene.dart`, `writing_scene.dart`) and `widgets/glyph_image.dart` are verbatim — the only edits are the asset paths (`assets/glyphs/` → `assets/makasar/glyphs/`) and one `withOpacity` → `withValues`, as the tally port did. `test/makasar/makasar_scene_test.dart` and `writing_scene_test.dart` are upstream's test files with only their package imports repointed. It is the one feature here with **two tabs**: *Draw* (one character at a time on dot-grid paper) and *Write* (`WritingLayer` on ruled paper — a whole row, each character grouped by position and read on its own, with Undo). Both canvases are alive at once and share the script, so `_select` points both at it; unlike Latin's and Greek's selectors this one **wipes** both (the layers do it themselves), since a reading taken as one script means nothing under the other. Only the pages were re-shaped into cord's house layout: upstream stacked a chip listing of the character set under each canvas *and* kept the full table on a page of its own, whereas here the table is the one listing — `pages/makasar_reference.dart` + `pages/reference_page.dart`, 50/50 beside the canvas on wide, behind an app-bar info button on narrow, as Latin/Greek/Cyrillic are — and it took over the chips' muting, so a row with no classifier is faded (`MakasarLayer.recognizedNamesFor`/`recognizedVowelsFor`, which is most of Lontara and every vowel sign). It sizes its columns off a `LayoutBuilder` rather than `MediaQuery`, since in the split it gets half the width the window reports. Upstream's `widgets/script_picker.dart` was not copied — the dropdown is inlined in the page's control bar like every other feature's. The **script dropdown** is Makasar vs Bugis (Lontara) and, unlike Latin's/Greek's alphabet selectors, it changes what is *recognized* (`MakasarRecognizer` dispatches on it), not just what may be reported. Its slug is the enum's own `.name` (`?script=bugis`); `scriptForSlug` lives in `pages/makasar_page.dart` and falls back to Makasar. **Bugis is mostly reference**: only the letters carrying a `LontaraLetter.shape` have a classifier (a test asserts those two stay in step), and nothing in the bundle renders the Buginese block, so its rows show the drawn letterform plus a `U+XXXX` codepoint where Makasar's show the character. Makasar's own glyphs need the bundled `NotoSerifMakasar` font, and both scripts' letterforms are the `assets/makasar/glyphs/` PNGs (`mak_*`/`lon_*`/`sign_*`) — a test checks the data and that directory stay in sync, so adding a character means adding its image. `test/makasar/makasar_page_test.dart` is upstream's page test re-aimed at that layout, plus cord's own three (initial script, unknown slug, narrow layout), sizing `tester.view` for the reason Latin's does; `reference_page_test.dart` is upstream's, reaching the second script by pumping it rather than by tapping a dropdown the page no longer has.
- **Hangul Grid** (`lib/hangul_grid/`, ported from the `hangul-word` app's *Syllable rows* tab) is the squared-notebook grid: one whole syllable per square, 4×2, with each row read out on a band beneath it. It is **the one tab, not the app** — the tab shell, the word list (`data/word_list.dart`), the target banner, and the other five tabs (one-letter, letter boxes, syllables, free writing, words) were not copied, so there is no word to hit, only free practice. It keeps its own `palette.dart` (warm paper/ink, so the page looks like paper rather than a Material surface) and its own `compose/` + `recognition/` next to the usual `engine/` and `scenes/`; `scenes/jamo_scene.dart` is upstream's verbatim, which is where `recognizeJamo`/`kRecognitionBox` come from — it is a *different* recognizer from `lib/hangul/scenes/hangul_scene.dart` (that one is ported from the `hangul` app) and the two are deliberately unrelated. `kHangulFont` is **null** here where upstream bundles a 2.3 MB NotoSansKR subset: browsers fall back for Hangul, same as the Hangul page. Tests under `test/hangul_grid/` are upstream's `syllable_rows_page_test.dart` (pumping the page instead of tab 3), `block_recognizer_test.dart`, and `square_reading_test.dart`.
- **Hanzi Grid** (`lib/hanzi/`, ported from the `hanzi` app's *Order up* tab) is the same squared-notebook idea one script over: one whole Han character per square, 4×2, each row read out on a band beneath it, with a 米 guide in each square. It is **the one tab, not the app** — the tab shell and the other five tabs, the brand/product pickers and their `data/vocabulary.dart`, the per-cell "stroke 3 out of order" verdicts, `recognition/character_attempt.dart` and the animated how-to-write demo (`painters/`) were not copied, so there is no character to hit, only free practice. Recognition is `recognition/character_recognizer.dart` verbatim: a square is compared *whole* against every glyph in the table with the same stroke count, on shape and on how the strokes meet — there is no per-glyph classifier and no `kRecognitionBox`, since it normalises against the character's own bounding box (which is why `scenes/grid_scene.dart` is `lib/hangul_grid/`'s `WordGridLayer` minus `normalizedCells`). `data/hanzi_strokes.dart` is a 956 KB **generated** table of 413 glyphs — never hand-edit it; it comes from `hanzi`'s `tool/` Node scripts. Beside it, `data/hanzi_glosses.dart` (pinyin + a one-word English meaning for all 254 distinct characters, so the page is readable by someone who does not read Han yet) is generated by **cord's own** `tool/hanzi_glosses.mjs` — the repo's only generator; run it from the repo root with Node **on the host**, since it fetches makemeahanzi's `dictionary.txt` and the devcontainer has neither Node nor a need for network. Kana get romaji instead of pinyin, and the three Japanese/Korean variant shapes (亀 値 飮) are aliased to the forms the dictionary files them under; both are spelled out in the generator rather than left implicit. Licences for all four data sources — including the dictionary's share-alike CC BY-SA 4.0 — are in `data/NOTICE.txt`. The same character is stored once per tradition (`ZH:`/`JA:`/`KO:` keys, each in its own stroke order), which is what lets the band say *whose* order you wrote it in; `variantsFor` answers that separately from the ranking, which stays order-insensitive — and is deliberately **not** narrowed by the script selector, since "you wrote this Chinese character in the Japanese order" is the point. The **script dropdown** (`data/hanzi_scripts.dart` — Everything / Chinese / Japanese / Korean / Hiragana / Katakana, the single source for the dropdown, the reference tabs and the search index) narrows the *candidate set*, which changes the reported confidence and not just the display. That needs the **one deliberate divergence from the verbatim recognizer**: an additive `where` filter parameter on `recognizeCharacter`, documented at its declaration. Filtering there rather than over the results is load-bearing — the returned list is already collapsed to one row per character, so filtering after the fact would report the wrong variant's score. Kana come from KanjiVG under `JA:` keys, so `hanzi_scripts.dart` is the only thing separating them from kanji. `kHanziFont` is **null** — upstream bundles no CJK font either. Tests under `test/hanzi/` are upstream's `character_recognizer_test.dart` verbatim, plus a grid-scene test carrying the stroke-to-square rules from its `order_slip_page_test.dart` and a page test in `test/hangul_grid/hangul_grid_page_test.dart`'s shape.
- The **Tally Marks** page (`lib/tally/pages/tally_page.dart`) is ported from the `tally_mobile` app: a canvas/game-loop engine (`lib/tally/engine/`) driving one `Scene` per tally system (`lib/tally/scenes/`), picked via a dropdown. The `TallySystem` registry (`lib/tally/data/tally_systems.dart`) is the single source for the dropdown, canvas, and search index. The engine and scene files are ported from `tally_mobile`/`tally_hand` (only deprecation/lint fixes applied — dropped redundant `gestures.dart` imports, `withOpacity` → `withValues`) — if you change a tally rule, keep in mind those upstream copies exist. A tally system is added by dropping a `*_scene.dart` with a `buildXScene()` under `lib/tally/scenes/` and appending a `TallySystem` entry.
- `web/manifest.json`, `web/index.html`, and `lib/main.dart`'s `seedColor` all share the brand color `#1F6F6B` — keep them in sync if it changes.
- PWA icons in `web/icons/` are generated (knotted-cord motif). Regenerate all five (`Icon-192`, `Icon-512`, `Icon-maskable-192`, `Icon-maskable-512`, `favicon.png`) together if the brand changes.
