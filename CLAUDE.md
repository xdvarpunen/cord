# cord

Flutter web app. This is developed on a Windows host, but **the Flutter/Dart SDK only exists inside the project's devcontainer** (`.devcontainer/Dockerfile`, `.devcontainer/devcontainer.json`) — it is never installed on the host. Do not expect `flutter`/`dart` to be on the host PATH; running them directly via Bash/PowerShell on the host will fail with "command not found".

## Running Flutter/Dart commands

The repo is bind-mounted into the devcontainer at `/workspace`. If a container is running (check `docker ps`), run commands via `docker exec <container> bash -lc "cd /workspace && flutter analyze"`. Otherwise open the folder in VS Code and "Reopen in Container", or build/run from `.devcontainer/Dockerfile` directly (see README). Ask the user before building/running a new container — that's heavier than exec-ing into one that's already up.

The container builds Flutter stable with web support enabled and Google Chrome installed. Port 8080 is forwarded for `flutter run -d web-server --web-port 8080`.

## Structure

- The app's pages live in one registry: `appPages` in `lib/pages/app_pages.dart`. Both the frontpage's link cards (`lib/pages/home_page.dart`) and the named routes (`lib/main.dart`) are generated from it. **To add a page**, add a widget under `lib/pages/` and append an `AppPage` entry — do not wire routes or home-screen cards by hand, or the two will drift.
- The **Search** page (`lib/pages/search_page.dart`, first registry entry / top link) filters `buildSearchIndex()` from `lib/pages/search_index.dart`, which is built from `appPages` + `tallySystems`. A page with its own dropdown content should contribute its items there (as the tally systems do) so search stays complete. Tally results open `TallyPage(initialSystem:)`, which reflects into `?system=` — keep that param if you refactor the tally page.
- **Every drawing feature — tally (`lib/tally/`), Futhark (`lib/furthak/`), Tifinagh (`lib/tifi/`), Hangul (`lib/hangul/`), Hebrew (`lib/hebrew/`), and the rest — lives under its own top-level folder and is deliberately kept fully isolated: nothing is shared between them.** Their assets are likewise grouped per feature under `assets/<feature>/` (most have none — they draw vectors). Each has its OWN copy of the engine (`scene.dart` + `game_canvas.dart`) and its own scene/data. Do NOT "de-duplicate" the engine copies into one shared engine, and do not have one feature import another's code — the separation is intentional and requested. The only shared code is the app shell (`main.dart`, `app_pages.dart`, `home_page.dart`, `search_page.dart`).
- **Futhark** (`lib/furthak/`, ported from the `furthak` app): desktop shows the rune reference table beside the canvas (50/50); narrow shows an info button opening the tabbed `reference_page.dart`. Runic glyphs need the bundled `NotoSansRunic` font (Flutter web has no system fallback for the Runic block).
- **Tifinagh** (`lib/tifi/`, ported from the `tifi` app) is **without the Neo-Tifinagh variants**: the dropdown offers the 5 Tuareg regions + Libyco-Berber, and `reference_page.dart` has Tuareg + Libyco-Berber tabs only (no `neo_tifinagh_scripts.dart` was copied). The recognizer scene (`tifinagh_scene.dart`) is otherwise verbatim and still contains its Neo-Tifinagh classifiers internally — they're just never selected. Needs the bundled `NotoSansTifinagh` font and the `assets/tifi/libyco_berber/` images (loaded by the scene via `rootBundle` and by the table via `Image.asset`).
- **Hebrew** (`lib/hebrew/`, ported from the `heb` app) is **without Paleo-Hebrew**: only the modern square alef-bet (22 letters + 5 final forms), so there is no script dropdown and none of the paleo reference data (`paleo_glyphs.dart`, `assets/paleo/`, `paleoSignRows`) was copied. The recognizer scene (`hebrew_scene.dart`) is otherwise verbatim and still contains its whole Paleo-Hebrew mode internally — `HebrewLayer.script` is simply never moved off `HebrewScript.modern`, which is why the `HebrewScript` enum and `paleoGlyphs`/`glyphIn` stay in `hebrew_letters.dart`. Same idiom as Tifinagh above; upstream `heb` also holds the paleo tests, so `test/hebrew/hebrew_scene_test.dart` is its test file minus that group. Hebrew glyphs need no bundled font (unlike Runic/Tifinagh, the block has system/browser fallbacks). Where several letters share a shape drawn alone (resh/yod, vav/final nun, dalet/final chaf) the recognizer reports one base glyph and names the group — see `HebrewLayer.sharedGroups`, which the legend reads too.
- The **Tally Marks** page (`lib/tally/pages/tally_page.dart`) is ported from the `tally_mobile` app: a canvas/game-loop engine (`lib/tally/engine/`) driving one `Scene` per tally system (`lib/tally/scenes/`), picked via a dropdown. The `TallySystem` registry (`lib/tally/data/tally_systems.dart`) is the single source for the dropdown, canvas, and search index. The engine and scene files are ported from `tally_mobile`/`tally_hand` (only deprecation/lint fixes applied — dropped redundant `gestures.dart` imports, `withOpacity` → `withValues`) — if you change a tally rule, keep in mind those upstream copies exist. A tally system is added by dropping a `*_scene.dart` with a `buildXScene()` under `lib/tally/scenes/` and appending a `TallySystem` entry.
- `web/manifest.json`, `web/index.html`, and `lib/main.dart`'s `seedColor` all share the brand color `#1F6F6B` — keep them in sync if it changes.
- PWA icons in `web/icons/` are generated (knotted-cord motif). Regenerate all five (`Icon-192`, `Icon-512`, `Icon-maskable-192`, `Icon-maskable-512`, `favicon.png`) together if the brand changes.
